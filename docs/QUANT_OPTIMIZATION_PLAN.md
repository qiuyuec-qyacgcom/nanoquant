# 短线量化系统全链路优化方案

> 目标：所有建议都服务于短线交易的三条盈利主线——**胜率、盈亏比、执行效率**。
> 短线不同于中长线：利润薄（一次 0.3~2%）、频率高、成本占比大、对延迟敏感。
> 因此本方案的评价标准始终是：这一条能不能让信号更准、让单笔赢/输比例更健康、让成交更快更省。

---

## 0. 执行摘要

本系统（nanoquant）的**工程底盘已经相当成熟**：执行链路有点差闸门、不确定成交处理、保护单、
精度对齐、幂等、对账；风控有日亏/回撤/连亏/止损熔断/冷却/敞口/同向/波动率缩放；
监控有分级告警、digest 聚合、死信、执行指标、运行时探针；回测有成本模型、参数网格、
walk-forward。这些是大部分自研系统最容易缺、也最值钱的部分。

但**信号层没有可证明的边缘**。2026-11 实测（币安 U 本位，BTC/ETH/SOL，walk-forward 样本外）：

| 方案 | 样本外 | 正期望折 |
|---|---|---|
| trend 5m/15m/30m/1h | 全负（-4% ~ -27%） | 0~1/3 |
| meanrev 5m | -6.7% / -4.8% / +0.7% | 2/3 · 1/3 · 2/3 |

结论：**先别急着加功能，先用已有但没被严格使用的验证能力把信号做实**，同时补齐几处
会让"看起来在跑、实际在漏"的执行缺陷。

### 优先级总表

| 优先级 | 主题 | 一句话 |
|---|---|---|
| **P0** | 验证纪律 + 扩大样本 | 短线信号没有边缘，加任何功能都是浪费；先跑 3~6 个月样本外 |
| **P0** | 成本敏感性 & 最小成交额 | 短线利润薄，手续费/滑点/资金费会吃掉全部 alpha |
| **P0** | 数据质量监控 | 未收盘 K 线、缺失因子已修，但要持续监控 staleness/gap |
| **P1** | 多周期 + 趋势强度过滤 | 用 HTF 过滤掉震荡噪声，是提升胜率最便宜的一步 |
| **P1** | 出场结构自适应 | 固定 1R 部分止盈 + 静态 ROI 表是"赢小输大"的根源 |
| **P1** | 执行前盘口二次确认 | 决策价与成交价的差，短线里就是利润 |
| **P2** | OMS/EMS 分层 & 订单状态机 | 架构级，为更复杂策略与多账户做准备 |
| **P2** | 相关性/因子拥挤风控 | 同向 cap 太粗，需要组合层面的风险预算 |

## 1. 现状总览（客观陈述）

| 环节 | 现状 | 成熟度 |
|---|---|---|
| 数据接入 | REST + WS 双通道，ticker/资金费率/OI 带 TTL 缓存；K线按需缓存；缺失语义刚修复 | 中 |
| 信号生成 | 5 因子加权（趋势/动量/量能/资金费/OI）+ LLM 复审 + 准入闸门；新增 meanrev 模式 | 中 |
| 交易策略 | trend/meanrev 双模式，部分止盈 + 移动止损 + 时间阶梯止盈 | 中 |
| 风控机制 | 日亏/回撤/连亏/止损熔断/冷却/敞口/同向/波动率缩放/杠杆钳制 | **高** |
| 回测评估 | 成本模型 + 参数网格（MIN_TRADES 护栏）+ walk-forward + 策略指纹 | 中高 |
| 实盘执行 | 市价/限价、不确定成交处理、保护单、精度对齐、互斥、异步落库、加仓合并 | **高** |
| 监控告警 | 分级告警（webhook/TG）、digest、死信、执行指标、运行时探针 | 中高 |

**一句话判断**：这不是一个"缺功能"的系统，而是一个"底盘扎实、但 alpha 没证明"的系统。
优化方向应该是**把已有能力用严 + 在信号与执行两端做确定性改进**，而不是堆新模块。

## 2. 数据接入

### 2.1 现状分析

- ticker/资金费率/OI 走 WS/缓存，设计合理。
- **已修复的隐患**：未收盘 K 线参与量能计算（量能闸门近乎永久关闭）；OI 只有单快照被当"变化 0"；
  缺失被当 0。这三处会让策略"看起来在算、实际拿到的是噪声"。
- **缺口**：只用单周期；没有 HTF（高周期）趋势过滤；没有盘口深度/订单流失衡，只有点差；
  没有成交流（aggTrades）；资金费率只有当前值，没有历史序列（判断"拥挤度反转"需要序列）。

### 2.2 成熟做法（主流量化系统）

- 数据层与策略层分离，统一提供"已对齐、已质量校验"的行情对象；
- 每个数据源带 staleness 标记：WS 断线后 REST 回退，且**让下游知道数据是回退的**（而不是静默用旧值）；
- 多周期聚合：HTF 用于过滤/定方向，LTF 用于择时入场；
- 盘口不平衡（bid/ask 量）是短线最廉价的前瞻信号之一。

### 2.3 改进建议

- **P0-1 数据新鲜度显式化**：`tickers`/`funding`/`oi` 的缓存命中与回退都要能区分
  "这是 20 秒内的值"还是"这是 WS 断线后的旧值"。当前缓存 TTL 到期才拉，但没有把
  "用了旧值"这件事暴露给信号层（信号层可能拿 3 分钟前的 ticker 做方向）。给特征加 `stale` 标志。
- **P0-2 资金费率历史序列**：缓存最近 N 个 8h 结算点的费率，用于计算费率分位数，
  替代当前"绝对费率 / 0.0008"的固定分母。短线跨结算点的仓位会被资金费惩罚，这是实打实的成本。
- **P1-3 多周期 K 线**：`_scan` 同时拉 HTF（如 15m）与 LTF（5m），HTF 只用于
  `entry_regime`/方向过滤，不参与入场。代价是每轮多一次 REST，但可以用 HTF 更长的 TTL 摊薄。
- **P2-4 盘口不平衡因子**：`book_tickers` 已用于点差闸门，扩展为 bid/ask 量比，
  作为量能因子的一个补充维度（放量 + 买盘主导 vs 放量 + 卖盘主导，含义完全不同）。

## 3. 信号生成

### 3.1 现状分析

- 5 因子加权 + 准入闸门 + 结构确认，可解释性好（reasons 落库）。
- **实测无边缘**：胜率与 `entry_threshold` 无关（28% 横盘），说明这 5 个因子在当前
  用法下对方向没有预测力。
- meanrev 模式已加，样本外明显好于 trend，但止盈目标用的是 `|z|·σ·0.9` 近似，
  不是真实中轨，且缺"极值后动能衰竭"的二次确认。

### 3.2 成熟做法

- 信号分级：**过滤条件**（决定能不能做，如趋势强度/波动率/流动性）与**触发条件**
  （决定何时入场，如突破/回踩）分开，不要混在一个加权分数里；
- 多因子用**等权/正交**而非凭感觉的手工权重（当前 0.32/0.26/0.18/0.12/0.12 无依据）；
- 因子在入场前做 IC 统计（当前完全没有）。

### 3.3 改进建议

- **P1-5 加趋势强度过滤（ADX/ATR 扩张）**：在 trend 模式里加一个"是否处于趋势体制"的硬闸门，
  只有趋势 + 顺势信号才放行。这是提升胜率最便宜的一步——5m 趋势跟随输就输在
  大部分时间在做震荡市里的假突破。
- **P1-6 meanrev 目标用真实中轨 + 动能衰竭确认**：止盈价 = 中轨而非近似；触发条件加
  "连续两根收盘回到带宽内"或"放量后缩量"的二次确认，避免在趋势启动前抢反弹。
- **P1-7 因子 IC 统计**：做一个轻量因子评估脚本，对每个因子单独算"信号后 N 根收益的
  IC/命中率"，把贡献为负的因子直接停用。比继续调权重有用得多。
- **P2-8 信号生成与组合层分离**：当前"打分→直接下单"耦合在一起。拆成"打分→候选池→
  组合层选币（按相关性/流动性/边际风险）→下单"，为后续多策略留接口。

## 4. 交易策略（出场结构）

### 4.1 现状分析

- 出场有：硬止损、固定 TP、时间阶梯 ROI、移动止损、部分止盈、信号反转、超时。
- **实测问题**：部分止盈在 1R 平 50%，剩余被移动止损很快扫掉，导致**均赢 R 只有 0.5~0.8，
  均亏 R 接近 1**——典型的"赢小输大"。关掉部分止盈后均赢升到 1R，但胜率下降。
- 静态 ROI 表（0.8%→0.2%）遇上 ATR 动态止损，会"在止损前落袋"（已加 `roi_min_r` 兜住，
  但 ROI 表本身仍未与波动率匹配）。

### 4.2 成熟做法

- 出场参数以 R 或 ATR 为单位，而不是绝对百分比；
- 部分止盈的触发倍数 ≥ 止损倍数（astra 用真实亏损换来的纪律，本项目已部分采纳）；
- 移动止损用 ATR 回撤而非固定百分比，避免被正常波动扫掉。

### 4.3 改进建议

- **P1-9 出场参数 ATR 化**：`trailing_pct` 从固定 0.8% 改为 `trailing_atr_mult`（如 1.5×ATR），
  ROI 表从绝对收益率改为 R 倍数表。这样一套参数跨周期、跨波动体制都成立。
- **P1-10 部分止盈自适应**：止盈比例随"波动率体制"变化——震荡市平多一点（落袋），
  趋势市平少一点（奔跑）。至少做成 `partial_tp_ratio` 按 `entry_regime` 分两档。
- **P2-11 分批出场状态机**：把"TP1 平 X%、TP2 平 Y%、剩余移动止损"显式建模，
  而不是现在"一次性部分止盈 + 无条件移动止损"的隐式组合。状态机更可测、更可解释。

## 5. 风控机制

### 5.1 现状分析（本系统最强的一块）

已有：日亏上限、最大回撤、连亏冷静期、止损熔断（窗口内 N 次止损暂停）、标冷却、
总敞口、同向集中、波动率缩放、杠杆钳制。且修复过"熔断原因回写导致永久熔断"这类
状态机 bug，质量不错。

### 5.2 缺口

- **组合层面是空的**：同向 cap（`max_same_direction`）只是"同向最多 N 个"，但没有
  相关性/共同因子暴露的度量。所有币同涨同跌时，N 个多仓本质上是一笔大杠杆多仓。
- **无强平价/保证金率监控**：这是短线 + 高杠杆下最致命的尾部风险——爆仓前没有预警。
- **无资金费惩罚**：跨结算点的仓位没有计入资金费成本。

### 5.3 改进建议

- **P1-12 强平价监控**：轮询/推送账户保证金率与各仓强平价，距强平价小于阈值（如 20%）
  时告警并可选自动减仓。短线高杠杆下这是保命功能，优先级高于任何信号改进。
- **P1-13 相关性敞口**：至少按"同方向名义额 × 相关系数近似（BTC 类/ETH 类/山寨类）"
  聚合敞口，替代纯同向计数。
- **P2-14 资金费计入成本模型**：回测与实盘 pre-trade 都把"预计持仓跨过的结算点 × 费率"
  计入预期成本，低于阈值的不开。

## 6. 回测评估

### 6.1 现状分析

- 已有：bar-by-bar 回测 + 手续费/滑点/点差/资金费、参数网格（MIN_TRADES=8 护栏、
  按期望 R 排序）、walk-forward（滚动样本外 + 过拟合缺口 + 参数一致性）、策略指纹。
- **不足**：样本只有 5 天（1500 根 5m）；没有成本敏感性分析；没有 bootstrap 置信区间；
  没有把"胜率/盈亏比"拆开看（summary 有 avg_win/avg_loss，但报告不突出）。

### 6.2 成熟做法

- 结果必须带**样本外 + 置信区间**，不能只报一个点估计；
- 成本模型做敏感性扫描：手续费 ±、滑点 ±，看结论是否翻转——短线策略尤其如此；
- 用 bootstrap 对交易序列重采样，给出期望 R 的分布，判断"正收益是不是运气"。

### 6.3 改进建议

- **P0-15 拉长样本到 3~6 个月**：现在一切结论建立在 5 天上。这是**第一优先**——
  在没拿到足够样本前，不要再改任何策略参数。CLI 已就绪：
  `python -m nanoquant.backtest.walkforward --symbols BTCUSDT,ETHUSDT,SOLUSDT --interval 30m --limit 10000`
- **P1-16 成本敏感性 + bootstrap**：在 walk-forward 汇总里加"手续费×2 / 滑点×2 后结论是否翻转"
  和"期望 R 的 95% 置信区间"。这两项能一眼区分"真边缘"和"运气"。
- **P2-17 防未来函数审查**：把"信号只用 t 之前的数据、成交用 t 之后的价格"写成
  断言/测试固化下来（`_closed_only` 已修了一处泄漏，还有没有别处需要系统排查）。

## 7. 实盘执行

### 7.1 现状分析（成熟）

已有：市价/限价 post-only、不确定成交（UncertainSubmission）查询回补、保护单（closePosition
algo 单）、精度对齐（tick/step）、平仓互斥 `_CLOSING`、异步落库、加仓合并（加权均价）、
保本上移重挂止盈。质量高。

### 7.2 缺口

- **决策价 ≠ 成交价**：信号用缓存 ticker 决策，下单用 MARKET 直接吃当前盘口，中间这一跳
  就是短线利润。已有 `max_spread_bps`/`max_slippage_pct` 闸门，但没做"下单前二次确认盘口"。
- **无 maker/taker 切换**：限价 post-only 追不上就错过，市价又吃滑点；没有"先挂限价、
  超时改市价"的中间态。
- **部分成交**：市价单基本全成交，但极端行情下 MARKET 也可能部分成交，当前未处理
  （`executedQty` 有读，但部分成交后的剩余保护单数量是否正确覆盖需要验证）。

### 7.3 改进建议

- **P1-18 下单前盘口二次确认**：`open_position` 前重取一次 `book_tickers`，
  若当前买一/卖一相对决策价偏差超过 `max_slippage_pct`，放弃或改价，而不是闭眼吃。
- **P1-19 限价转市价的超时机制**：`limit_post_only` 挂单 N 秒未成交 → 撤单改市价
  （或放弃，取决于配置）。在"追不上"和"滑点大"之间取一个可控的中间态。
- **P2-20 订单状态机（OMS）**：把下单→挂单→成交/部分成交/撤单→保护单 显式建模，
  当前散落在 broker 里的 if/else 迟早会在更复杂策略下出状态错乱。这是架构级，先记下。

## 8. 监控告警

### 8.1 现状分析（中高）

已有：分级告警 + webhook/Telegram + digest 聚合 + 静默时段 + 死信 + 执行指标 + 运行时探针 + 数据保留。覆盖了"出错了能知道"。

### 8.2 缺口

- 告警偏"事后"（平仓、熔断、报错），缺**事前/实时**告警：
  - 强平价逼近（见 P1-12）；
  - 数据源延迟/断线超过阈值多久没恢复；
  - 本地账本与交易所持仓漂移（数量/价格对不上）；
  - 下单反复被拒/超时（不是单次报错，而是"连续 N 次"才升级）。

### 8.3 改进建议

- **P1-21 实时健康告警**：数据新鲜度（WS/REST 断线时长）、持仓漂移、连续下单失败，
  用"阈值 + 持续时间"触发，而不是单次错误就打。digest 已有，补一个"健康分"面板。
- **P2-22 告警分级与 runbook**：给每条告警绑一个 runbook（该做什么、谁负责、能不能自动恢复），
  让告警从"通知"变成"可执行的运维指令"。

## 9. 路线图建议

### 第一阶段（P0，1 周内，不写新策略代码）

1. 拉 3~6 个月样本，跑 walk-forward，确定"到底有没有边缘"；
2. 成本敏感性扫描 + bootstrap，排除"负收益是运气差"的安慰剂；
3. 数据新鲜度显式化（`stale` 标志贯穿特征）。

**产出**：一份"这个信号能不能做"的裁决书。做不出正期望，下面都不用做。

### 第二阶段（P1，2~4 周，围绕胜率/盈亏比）

4. 趋势强度过滤 + meanrev 中轨止盈 + 动能衰竭确认（胜率）；
5. 出场 ATR 化 + 部分止盈自适应（盈亏比）；
6. 下单前盘口二次确认 + 限价转市价（执行效率）；
7. 强平价监控 + 实时健康告警（尾部风险）。

### 第三阶段（P2，架构级）

8. 因子 IC 评估 + 信号/组合层分离；
9. OMS/EMS 分层与订单状态机；
10. 相关性/因子拥挤风控 + 资金费计入成本模型。

## 10. 一句话收束

这个系统缺的不是模块，而是**证据**。工程底盘（执行、风控、监控）已经能保证
"不把错单放出去、亏了能停下来"；但信号层没有证明自己能赚钱。所以真正的优化顺序是：
**先用已有验证能力把 alpha 证伪或证实，再谈加功能。** 短线尤其如此——利润薄，
一个没有正期望的策略，加再多因子也只是让亏损更精致。

| 总盈亏（毛） | **-743 USDT**，扣费后 -1182 |
| 盈亏比 PF | 0.735（均赢 60.6 / 均亏 87.6） |
| 手续费 | 439 USDT（占账户 8.8%，66 笔均摊 6.7U/笔） |
| 账户 | 5000 → 2650（**5 天 -47%**） |
| 名义成交额 | 71.3 万 USDT（换手极高） |

### 头号元凶：移动止损

按出场原因拆：

| 出场 | 笔数 | 盈亏 | 胜率 |
|---|---|---|---|
| roi（时间阶梯止盈） | 22 | **+1713** | 100% |
| partial_tp（部分止盈） | 6 | **+256** | 100% |
| timeout（超时） | 13 | -74 | 46% |
| **trailing_stop（移动止损）** | **24** | **-2639** | **0%** |

`trailing_stop` 24 笔全亏，把 roi + partial_tp 赚的 1970 全吐掉还倒贴 600。

**根因**：`trailing_pct=0.8%` 是固定回撤，小于 ATR 止损距离（0.7%~4%），而且移动止损
**从开仓那一刻就 arm**（`peak_price` 起始于 entry）。于是任何一笔没先涨够、回撤 0.8% 的单，
都会在 ATR 止损之前被噪声扫掉。实测这 24 笔里绝大多数 peak 只高出 entry 0.2~0.5%，
从没真正盈利过。

**已修复**：新增 `trailing_arm_r`（默认 1.0）——浮盈先走到 1 倍风险，移动止损才接管；
否则交给 ATR 止损。回测同步修复（保持回测=实盘）。测试 `test_detect_exit_trailing_stop`
锁住"未到 1R 不得触发"。

### 两个数据陷阱

1. **滑点在模拟盘是 0 bps**：demo 成交按 mark 价精确成交，没有滑点模型。
   亏损集中在低流动性山寨币（ZEC -541、ARIA -407、INIT -329、ON -315），
   这些币实盘点差可能 10~50 bps，真实亏损会比模拟更差。流动性好的 BTC/ETH/ARB 反而是赚的。
2. **手续费是隐性杀手**：439U 手续费 / 66 笔，短线高频下这笔钱直接决定盈亏。

### 结论

模拟盘实盘数据**证实**了 walk-forward 的结论（信号没有正期望），并且把亏损拆得更清楚：
**不是"不会赢"（roi/partial_tp 能赢），而是移动止损把赢的全部扫光 + 手续费蚕食。**
修复移动止损后值得重跑一轮模拟，看能否从 -47% 收敛到接近打平；但趋势信号本身
是否能在拉长样本后转正，仍取决于 P0 的 walk-forward。
