# 策略模块评审：修了什么、以及一个不太好听的结论

参考对象：`F:\cb\astra-quant-agent`（4 万行，策略/执行/自进化）。
本文只记录**经过实测**的结论，不复述对方文档的承诺——那份仓的文档与代码有系统性偏差
（`load_adaptive_config()` 是空桩、`calculus` 已退役但文档仍在、Kelly 只出现在注释里）。

---

## 一、修掉的四个真实缺陷

### 1. 用"还没走完的那根 K 线"判量能（影响最大）

行情接口返回的最后一根 K 线是**未收盘**的，它的 `volume` 只是"这一根到目前为止"的量。
拿它除以 20 根完整 K 线的均量，量比会系统性偏小。

修前实测（BTC/ETH/SOL/XRP/DOGE，5m）：

```
量比 0.11 ~ 0.16   闸门要求 >= 0.8   → 5 个标的全部"量能不足"
```

修后（剔除未收盘那根）：

```
量比 0.43 ~ 0.65，历史分布中位 0.76，约 45% 的 K 线能过闸门
```

也就是说，**这个闸门在修之前几乎永久关闭**，策略只能偶尔在 K 线刚收盘那一刻开仓。
判定方式不依赖外部传周期：用相邻两根的时间差推出单根时长，末根结束时间未到即视为正在形成；
历史回测数据天然满足"已收盘"，不会被误删。

### 2. OI 因子的权重一直在，值永远是 0

`build_features` 只写入 `open_interest`（持仓量绝对值），从未写入 `oi_change_pct`；
而打分读的是 `features.get("oi_change_pct", 0.0)`。

后果：OI 因子贡献恒为 0，但它的 12% 权重仍留在分母里
→ **所有信号被系统性打了 0.88 折**，而且看不出来。

修法：worker 维护上一轮 OI 快照自行计算 ΔOI；第一轮没有基线就把该因子标记为**缺失**
（而不是 0），权重跟着从分母剔除。

### 3. 缺失被当成中性

`ema()` 在 K 线不足时会**悄悄缩短周期**（返回一个"周期 10 的 EMA55"），
`rsi()` 返回 50，`atr()`/`macd_hist()` 返回 0。这些值全部落在"中性"上，
于是"没数据"和"数据表明中性"在下游完全无法区分。

修法：`build_features` 输出 `ok` / `missing`，打分只对可用因子归一化；
趋势因子不可用时直接拦下并说明"K 线不足 N 根"，而不是给个 0 分当观望。
缺失值写成 `None` 而非 `0.0`——提示词的数值白名单会把 `None` 丢掉，
模型看到的是"没有这一项"，而不是"费率恰好是 0"。

### 4. 时间阶梯止盈不等 R

`roi_table` 是静态收益率表（0 分钟 0.8%、120 分钟 0.2%），而止损是 ATR 动态的。
止损 1% 时，0.8% 的止盈只有 0.8R；止损 3% 时只有 0.27R——**在止损之前落袋，锁定小于 1R**。
这正是 astra 用真实亏损换来的那条纪律（`risk_constants.py:106-111`：
"分批平仓触发倍数必须 ≥ 止损倍数，否则赢小输大"）。

修法：新增 `roi_min_r`（默认 1.0），低于 N 倍风险不主动了结；回测同步应用同一规则，
避免"回测算盈利、实盘不平仓"。

## 二、顺带补的三项

| 项 | 内容 |
|---|---|
| 盈亏比硬底线 | `min_risk_reward`（默认 2.0），止盈被 8% 上限截断后凑不够就拒绝开仓。R:R=2 只需 33% 胜率即可正期望，R:R=1.1 需要 48% 以上 |
| RSI 体制自适应 | 同一个 RSI 65，在多头里是"健康"、在空头里是"反弹卖点"；RSI 82 在多头里是"别追"而不是买入 |
| 震荡市时间止损 | 入场时 `|EMA 间距| < chop_ema_gap_pct` 视为震荡，时间止损从 180 分钟缩到 90 分钟（与 astra 的 `is_chop_pos` 同思路） |
| 策略版本指纹 | 影响信号语义的参数做 sha256 取前 8 位，随信号落库并写进持仓 `features`，复盘能区分"策略版本问题"还是"执行问题" |

## 三、单段回测：这些修复没有让策略变成赚钱的

用真实行情（币安 U 本位，1500 根）跑 `run_backtest`，BTC/ETH/SOL 三标的合计：

| 周期 | 笔数 | 胜率 | 期望 | PF | 平均总收益 |
|---|---|---|---|---|---|
| 5m | 297 | 26.9% | -0.53R | 0.21 | -52.6% |
| 15m | 441 | 37.2% | -0.30R | 0.47 | -44.2% |
| 30m | 544 | 39.9% | -0.22R | 0.53 | -40.3% |
| 1h | 603 | 40.3% | -0.14R | 0.69 | -28.1% |

分数阈值扫描（5m）：`entry_threshold` 从 0.25 提到 0.70，**胜率一直在 28% 横盘**，
期望反而略微变差（-0.51R → -0.58R）。真有边缘的话，收紧阈值应该让期望单调变好，
而不是只减少笔数。

> ⚠️ 这一节是**单一样本**的结论，曾被误读成"切到长周期就能改善"。
> 下一节的 walk-forward 推翻了那个建议。

## 四、Walk-forward：切周期救不了它

样本内挑参数、样本外检验（`backtest/walkforward.py`，3 折滚动，训练 600 根，
网格含 `entry_threshold` / `sl_atr_mult` / `tp_atr_mult`）。样本外收益：

| 方案 | BTCUSDT | ETHUSDT | SOLUSDT | 正期望折 |
|---|---|---|---|---|
| trend 15m | -26.6% | -14.4% | -26.4% | 0/3 · 0/3 · 0/3 |
| trend 30m | -27.1% | -13.4% | -20.7% | 0/3 · 1/3 · 0/3 |
| trend 1h | -22.0% | -15.7% | -16.4% | 0/3 · 0/3 · 0/3 |
| meanrev 5m | -6.7% | -4.8% | **+0.7%** | 2/3 · 1/3 · **2/3** |
| meanrev 15m | -2.9% | -6.2% | **+5.1%** | 1/3 · 0/3 · 1/3 |
| meanrev 30m | -3.1% | -8.9% | -16.9% | 1/3 · 1/3 · 0/3 |

三条结论：

1. **"切到长周期"不成立**。15m/30m/1h 的样本外全为负，15m 甚至最差。
   之前那张"周期越长越好"的表是单段回测的错觉，差异在噪声范围内。
2. **均值回归明显好于趋势跟随**，尤其 5m：BTC/SOL 有三折中两折为正，
   SOL 样本外还是小正。这和"5m 级别趋势跟随被噪声与手续费吃掉"的机制一致。
3. **但仍然不能上线**。meanrev@5m 的 ETH 是 -4.8%，BTC -6.7%，
   合计仍为负；单折样本 20~40 笔，统计上还撑不起"有边缘"的判断。

## 五、因此做出的默认值变更

| 项 | 改为 | 依据 |
|---|---|---|
| `strategy.auto_entry` | **false** | 没有任何配置在样本外为正，默认不该拿真钱去试。信号照常落库供观察 |
| `strategy.timeframe` | 保持用户设置（15m） | 三个周期样本外都负，硬换成 30m 没有依据 |
| `strategy.mode` | 保持 `trend`，另提供 `meanrev` | 换成默认等于把未验证的假设直接上线；面板可一键切 |

`auto_entry=false` 只挡"策略自主开仓"，**不影响 Telegram 跟单**，
也不影响已有仓位的止损/止盈管理。

## 六、下一步该做什么

按性价比排序：

1. **先观察，不要交易**。`auto_entry=false` 已经生效。信号继续落库，
   对照盘面看几天，比继续调参更有信息量。
2. **要验证"有没有边缘"，先扩大样本**。现在的结论建立在 1500 根（约 5 天）上，
   折内只有 20~90 笔。至少取 3~6 个月、覆盖不同波动体制再跑一次 walk-forward，
   命令现成：

   ```bash
   cd backend
   python -m nanoquant.backtest.walkforward --symbols BTCUSDT,ETHUSDT --interval 30m --limit 3000
   ```

   输出的 `overfit_gap_pct` 是"样本内均值 − 样本外均值"，越大说明参数越是在拟合噪声；
   `positive_folds` 是正收益折数，全 0 就别再看收益率了。
3. **均值回归方向值得继续挖**，但要补两件事再谈上线：
   - 回归目标用真实中轨（现在用 `|z|·σ·0.9` 近似），并在触发时按中轨动态止盈；
   - 加入"极值后动能衰竭"的第二重确认（连续两根收盘回到带宽内），
     现在的实现只看单根 z，容易在趋势启动前抢反弹。
4. **不要做网格搜索**。`grid.py` 已经加了 `MIN_TRADES=8` 的护栏和按期望 R 排序，
   就是为了拦住"3 笔单赚 50% 夺冠"。样本不变的情况下，搜得越细，过拟合越重。

---

## 七、给"这个项目值不值得继续"的判断

值得，但要换个定位。

现在的价值不在"策略能赚钱"（还没证明），而在：

- 执行链路是对的（点差闸门、部分止盈按步进取整、幂等、止损必挂、跟单五类事件）；
- 风险闸门是硬的（日亏损、回撤、连亏、止损熔断）；
- 现在有了**可验证性**：改参数能立刻知道样本外是变好还是过拟合。

这三样比一个"回测很好看"的策略值钱得多。策略是最后一层，也是最容易自欺的一层——
astra 那个仓 4 万行，真正能用的也不是它的选币逻辑，而是那套执行纪律。
