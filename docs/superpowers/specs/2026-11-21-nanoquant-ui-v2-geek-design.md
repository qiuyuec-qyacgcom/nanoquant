# NanoQuant UI v2：石墨蓝图极客终端

## 意图

现有前后台的问题不是单纯“配色不好看”，而是三套气质叠在一起：

- 前台是象牙白 + 金色 + 大衬线，偏品牌画册；
- 后台是黑金 + 细边框 + 小号等宽字，偏常见交易所模板；
- 金色同时承担品牌色、主操作色和警示色，弱化了盈亏语义和操作层级。

本次重做的目标是把前后台统一成一套**黑底、极客、可长时间盯盘**的视觉系统：以石墨蓝黑为骨架，电光蓝为唯一品牌主色，绿色/红色只表示盈亏，保留少量终端窗口、状态灯、命令栏和括号角细节。

## 选择结果

概念稿三选一，用户选择：

**B 石墨蓝图为主 + A 磷光终端细节**

- 主视觉：石墨蓝黑、技术网格、细边框、等宽数据。
- 保留 A 的终端窗口、状态灯、命令栏、扫描线细节，但不使用全局磷光绿。
- 不使用 C 的酸性绿/品红作为主色，避免金融工具感被赛博娱乐感盖过。

## 目标

- 前台首页、登录页、后台 Shell、总览、参数配置、风险与持仓、移动端总览统一换肤。
- 全站去掉金色主视觉和后台衬线标题；主色统一为蓝图蓝。
- 后台提高信息层级和留白，减少“每个面板都用边框抢注意力”的问题。
- 引入极客细节但不牺牲可读性：命令栏、状态灯、终端窗、坐标标签、括号角、等宽数字。
- 保留现有业务逻辑、接口、无感刷新、权限与数据流。

## 非目标

- 不新增交易功能、不改后端 API、不改数据库 schema。
- 不做全站动画系统，不做复杂 3D、粒子、WebGL。
- 不重写所有业务页面；先完成全局 token + Shell + 六个核心页面，其余页面继承全局风格后逐页微调。
- 不改变现有信息架构和路由，除非页面布局必须调整。

## 视觉系统

### 色彩 Token

```text
--bg:          #05080d
--bg-2:        #07101b
--panel:       #0a111c
--panel-2:     #0d1726
--panel-3:     #111f33
--line:        rgba(104, 160, 255, 0.16)
--line-strong: rgba(104, 160, 255, 0.34)
--text:        #e8f0fb
--muted:       #8193ad
--dim:         #52647e
--accent:      #4da3ff
--accent-2:    #84c4ff
--accent-soft: rgba(77, 163, 255, 0.09)
--up:          #4ad6a4
--down:        #ff5f7e
--warn:        #ffb84d
```

规则：

- 金色不再作为品牌/按钮/导航主色；如必须保留品牌识别，只允许出现在极小的 logo 辅助细节，默认不使用。
- 绿色只表示盈利/通过/运行中，红色只表示亏损/拒绝/风险。
- 主按钮使用蓝图蓝实底 + 深色文字；次按钮为透明底 + 蓝色边框。
- 背景使用低对比技术网格和局部蓝色径向光，不使用大面积渐变。

### 字体

- UI 正文：`Segoe UI / Microsoft YaHei / PingFang SC`
- 数字、代码、标签：`Cascadia Code / Consolas / SFMono-Regular`
- 后台标题不再使用衬线体；前台标题使用高字重无衬线，保留少量终端式等宽 eyebrow。
- 数字统一 `font-variant-numeric: tabular-nums`。

### 形状与细节

- 圆角：2px；不使用大圆角。
- 边框：1px 半透明蓝灰线；重点面板用括号角/角标，不堆叠粗边框。
- 极客细节：
  - 终端窗口：三点状态灯、`NQ / LIVE VIEW`、扫描线只出现在图表/终端窗内部。
  - 后台顶栏：`⌘K 搜索 / 命令` 命令栏。
  - 状态灯：运行中/连接中/离线使用小圆点和文字，不只靠颜色。
  - 面板角标：右上/右下括号角。
  - 数据标签：`SYSTEM STATE / RISK BUDGET / EXECUTION CHAIN` 等短英文 eyebrow。
- 动效：状态灯缓慢呼吸、扫描线极低透明度；支持 `prefers-reduced-motion` 时全部关闭。

## 页面方案

第一版重排 5 个核心页面：前台首页、登录、后台总览、参数配置、系统诊断；同时完成共享 Shell 与 390px 响应式验收。其余后台页面继承全局 token 和组件，只清理硬编码颜色，不重排业务结构。

### 1. 前台首页

- 保留现有 `KlineBoard`，位置调整为 Hero 下方的独立行情区；不删除行情功能。
- Hero 右侧终端窗的权益曲线和三条持仓是 `DEMO / ILLUSTRATIVE` 静态示意，必须明确标注；真实公开数据仍来自 `publicOverview` 和 `publicPerformance`。
- ticker 使用公开行情/概览数据；公开接口没有真实持仓和权益序列，本次不扩展后端 API。
- 顶部导航：左侧 NQ 标记 + NanoQuant，中央“首页/行情/观点/关于”，右侧引擎状态 + “进入终端”。
- 视觉：石墨蓝黑 + 40px 蓝图网格 + 蓝色径向光；终端窗使用 A 的扫描线/状态灯，但颜色为蓝图蓝。

### 2. 登录页

- 左右分栏：左侧品牌/终端叙事，右侧登录表单。
- 保留现有安全提示、首次登录改密、TLS/会话说明。
- 表单使用深色面板、蓝色 focus ring；不再使用大面积象牙白右栏。
- 左侧使用命令提示符式小字和运行状态，不使用大衬线标题。

### 3. 后台 Shell

- 侧栏 220px：品牌、分组导航、计数、底部 LIVE / UDS 状态。
- 顶栏 62px：页面标题、副标题、运行状态、时间、命令栏、头像。
- 内容区 24px 内边距；面板间距 10px；活动导航使用蓝色左边线 + 淡蓝底。
- 全局替换金色 active 状态。
- 顶栏命令栏 v1 只做客户端页面导航/搜索，不执行启停引擎、平仓、切换环境等高危操作；这些仍走原有按钮与确认流程。

### 4. 总览（含风险与持仓）

- 不新增 `/admin/risk` 路由；现有 `DashboardView` 同时承载 KPI、风险预算和当前持仓。
- 四张 KPI：账户权益、已实现盈亏、最大回撤、运行仓位。
- 主图 1.45fr 权益曲线 + 0.75fr 风险预算环图。
- 当前持仓表：标的、方向/杠杆、数量、开仓/标记、未实现盈亏、止损/止盈。
- 底部状态条：引擎、UDS、下一次扫描、审计提示。
- 系统诊断页保持独立，仅换肤，不合并到总览。

### 5. 参数配置

- 保留现有“左侧分组 + 中间表单卡片 + 右侧风险画像”的结构。
- 去掉金色标题与金色保存按钮；改为蓝图蓝主按钮。
- 表单卡片按“执行/风险/熔断/通知”分组，使用 1px 线和小标题，不使用重阴影。
- 保存栏固定在底部，显示未保存数量、放弃、保存并生效。

### 6. 系统诊断（换肤）

- `SystemView.vue` 仍是日志、健康检查、归档、执行 sidecar 和诊断页，不改业务结构。
- 只替换全局 token、面板、表格、状态灯和按钮，保持现有诊断能力。

### 7. 移动端总览（响应式）

- 不新增移动路由或独立视图；`DashboardView` 与 `ShellLayout` 做 390px 断点适配。
- 390px 截图作为验收标准，桌面端与移动端共用同一套 token。
- 移动端侧栏沿用现有抽屉；总览卡片纵向堆叠，持仓表改为卡片化行，保留风险与盈亏语义。

## 组件改造

- `frontend/src/styles/redesign.css`：替换全局 token、Shell、按钮、面板、KPI、表格、标签、表单、图表容器。
- `frontend/src/styles/main.css`：清理残留金色/米色硬编码。
- `frontend/src/layouts/ShellLayout.vue`：后台侧栏/顶栏/命令栏/状态灯。
- `frontend/src/layouts/SiteLayout.vue`：前台导航、页脚、ticker。
- `frontend/src/views/site/HomeView.vue`：前台 Hero + 终端窗。
- `frontend/src/views/LoginView.vue`：深色登录分栏。
- `frontend/src/views/DashboardView.vue`：KPI/图表/风险/持仓。
- `frontend/src/views/StrategyView.vue`：参数分组、保存栏。
- `frontend/src/views/SystemView.vue`：系统诊断页换肤，不改诊断结构。
- `frontend/src/components/CommandPalette.vue`（新增）：客户端页面导航/搜索，不接入启停、平仓、切换环境等高危操作。
- `frontend/src/components/KlineBoard.vue`、`KlineChartPanel.vue`、`Sparkline.vue`：图表色板、网格、轴标签统一。
- `frontend/src/components/Modal.vue`、`EnvironmentSwitch.vue`、`EventFeed.vue`：跟随全局 token。

## 实施策略

1. 全局 token + Shell + 前台首页 + 登录 + 后台总览（含风险/持仓）。
2. 参数配置 + 系统诊断换肤 + 导航命令栏。
3. 390px 后台总览响应式验收。
4. 其余后台页面做 token 继承与金色/米色残留清理，不重排业务结构。
5. 每个阶段截图对比 1440 桌面和 390 移动，先看视觉再继续扩展。

## 验证

- `npm --prefix frontend run typecheck`
- `npm --prefix frontend test`
- `npm --prefix frontend run build`
- 视觉检查：
  - 1440 前台首页、登录、后台总览（含风险/持仓）、参数配置、系统诊断
  - 390 后台总览
- 检查无金色主色残留、无后台衬线标题、无绿色品牌主色。
- 命令栏仅能导航到已有页面，不能触发交易/启停/平仓。
- 检查键盘 focus ring、对比度、`prefers-reduced-motion`。

## 风险

- 现有页面存在大量硬编码金色/米色，需逐页清理，不能只改 `redesign.css`。
- ECharts/K线 canvas 颜色不一定继承 CSS token，需要单独传色板。
- 参数页和风控页业务字段多，重排时必须保持现有字段、校验、保存逻辑不变。
- 登录页和前台首页涉及品牌识别，先以概念稿为准，不在实现阶段再次改方向。
